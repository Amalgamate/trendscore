# Phase Template

Use this template for every authentication migration phase.

## Phase Goal

State the concrete outcome of this phase.

## Why This Phase Exists

Explain the risk this phase reduces or the capability it prepares.

## Files Allowed To Modify

List exact files or directories.

## Files Forbidden

List exact files, directories, or module areas that must not be touched.

## Database Changes Allowed?

Answer `Yes` or `No`.

If yes, list the allowed schema and migration boundaries.

## API Changes Allowed?

Answer `Yes` or `No`.

If yes, list allowed request/response contract changes.

## UI Changes Allowed?

Answer `Yes` or `No`.

If yes, list allowed screens and behavior.

## Tests Required

List unit, integration, API, UI, and manual verification required for this phase.

## Acceptance Criteria

List observable conditions that must be true before marking the phase complete.

## Rollback Strategy

Explain how to undo the phase safely.

## Definition Of Done

List the exact completion requirements.

## Next Phase Prerequisites

List what must be true before the next phase can start.
